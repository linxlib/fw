# astp 整体解析流程

> 本文档已按**本项目（`github.com/linxlib/fw/v2`）的 `astp` 包**重写。
> 早先版本描述的是外部旧版 `astp` 库的流程（从 `main.go` 入口递归、`findType`/`parseDir`、
> 未解析类型打标记后处理、`handleExistsMethods` 等），当前仓库内的 `astp/parser.go`
> 采用的是「整目录遍历 + 单趟摊平」模型，两者已不同。

## 解析流程

入口有两个，都在 `astp/parser.go`：

- `Parser.ParseProject(rootDir)`：从 `rootDir` 向上找 `go.mod` 得到模块信息，
  然后 `filepath.Walk` 遍历所有目录（跳过 `vendor`、`node_modules`、`.` 开头目录），
  对每个含 `.go` 文件的目录调用 `Parser.Parse`。**跨包引用不做递归解析**，
  只解析本模块内的包。
- `Parser.Parse(dir)`：解析单个目录。

单目录解析（`Parser.Parse` → `loadPackage` → `parseFile`）：

1. `loadPackage(dir)`
   - `build.Default.ImportDir(dir, 0)` 取包名与 `GoFiles` 列表（`CgoEnabled=false`）
   - 对每个文件 `parser.ParseFile(fset, path, nil, parser.ParseComments|parser.AllErrors)`；
     解析失败的文件直接 `continue` 跳过
   - 用 `filepath.Rel(moduleDir, dir)` 把目录换算成模块内包路径（`ParseProject` 才需要，
     `modulePath`/`moduleDir` 为空时退回 `bpkg.ImportPath`）
   - 在 `project.Packages[pkgPath]` 下登记 `Package`
2. 按 `p.parsedFiles` 去重后逐文件 `parseFile`
3. `parseFile` 按声明走两条分支：
   - `*ast.GenDecl`
     - `Tok == CONST` → `parseConstDecl`（常量 + 顺带识别枚举）
     - 其余 → 遍历 `Specs`：`*ast.TypeSpec` → `parseTypeSpec`；`*ast.ValueSpec` → 变量
   - `*ast.FuncDecl` → `parseFuncDecl`
4. 目录内所有文件解析完，`Parse` 返回；`ParseProject` 走完所有目录后统一收尾

### 结构体的解析（`parseTypeSpec`）

```
TypeSpec
├── Doc（decl.Doc，回退 spec.Doc）
├── Name / PkgPath
├── TypeParams → GenericSpec（含 Constraints）
└── Type 的具体形态
    ├── StructType    → Fields（parseFields）
    ├── InterfaceType → Methods（parseInterfaceMethods，仅方法签名）
    ├── Ident         → AliasOf
    ├── SelectorExpr  → AliasOf（带包路径）
    ├── ArrayType     → ElemType
    ├── MapType       → KeyType + ElemType
    ├── StarExpr      → ElemType
    └── FuncType      → Methods（签名式函数类型）
```

`parseFields` 对每个 `ast.Field` 只取 `Type` 与 `Doc`（`f.Doc` 回退 `f.Comment`）；
`f.Names` 为空视为匿名嵌入字段（`Embedded = true`）。

### 函数 / 方法的解析（`parseFuncDecl`）

函数与方法共用同一条路径，靠 `decl.Recv` 区分：

```
FuncDecl
├── Name / PkgPath / Doc
├── Recv（decl.Recv 非空时）→ parseTypeRef(recv.Type)
│     └── 泛型结构体实例化（如 *Stack[T]）落在 Recv.Generic.args
├── TypeParams → GenericSpec（含 Constraints）      ← 方法自身类型参数（Go 1.27 泛型方法）
├── Params  → parseParams(decl.Type.Params)
├── Results → parseParams(decl.Type.Results)
└── 归属：Recv 非空 → 追加到 pkg.Types[Recv.Name].Methods
         否则     → pkg.Functions[Name]
```

- **Go 1.27 方法泛型**：`go/parser` 会把方法自身类型参数无条件写进
  `decl.Type.TypeParams`（无 GODEBUG/GOEXPERIMENT 门控），因此这一步对方法同样生效，
  无需改动 `parser.ParseFile` 的调用方式。
- 方法自身类型参数作为「已声明占位」保留：具体类型只在调用点可知，
  静态解析阶段不实例化替换，也不推断调用点实参。
- **接口方法不允许声明类型参数**（Go 1.27 规格限制）。`parser.ParseFile` 直接报错，
  `loadPackage` 对解析失败的文件是 `continue` 跳过，所以无需在 astp 内特判。

### 类型引用解析（`parseTypeRef`）

递归地把 `ast.Expr` 降级成 `TypeRef`，只保留**最外层形状 + 名字/包路径 + 嵌套子引用**：

| `ast.Expr` | `TypeRef` |
| --- | --- |
| `Ident` | `{name, kind}`（`isBasicType` 命中 → `basic`，否则 `struct`） |
| `SelectorExpr` | `{name: Sel, pkg_path: X, kind: struct}` |
| `StarExpr` | 解析 `X` 后把 `Kind` 改为 `pointer` |
| `ArrayType` | `{kind: slice, elem_type}` |
| `MapType` | `{kind: map, key_type, elem_type}` |
| `IndexExpr` | 解析 `X` 后挂 `generic.args = [Index]` |
| `IndexListExpr` | 解析 `X` 后挂 `generic.args = Indices` |
| `InterfaceType` | `{kind: interface}`（内部方法集丢弃） |
| `FuncType` | `{kind: func}`（签名丢弃） |
| `ParenExpr` | 解析 `X` |
| `UnaryExpr`（`~T`） | 解析 `X`（`~` 本身不落库） |
| 其他 | `{kind: basic}` |

### 收尾：类型参数标记（`finalizeTypeParams`）

在 `Parse` / `ParseProject` 末尾执行一遍后处理：

1. 遍历 `project.Packages[*].Functions` 与 `project.Packages[*].Types[*].Methods`
2. 对每个 `Func` 计算签名内可见的类型参数名集合：
   - 自身 `Func.Generic.Params` 的名字
   - 若是方法，再取接收器基类型 `pkg.Types[Recv.Name].Generic.Params` 的名字
     （方法必与接收器类型同包，所以精确；放在末尾执行因此不受源码声明顺序影响）
3. 把 `Params` / `Results` / `Recv` 中**直接**以该名字为类型的 `TypeRef.Kind`
   改写为 `typeparam`（`KindTypeParam`）
   - 条件：`Kind == KindStruct && PkgPath == ""` 且名字在作用域内
   - `[]T` 的 `elem_type`、`map[K]V` 的 `key_type`/`elem_type` 会被标记
   - `*V` 保持 `kind: "pointer"`（指针形状更有价值，不改写）
4. 幂等：重复执行结果不变

这一步让调用方能区分「这是一个待定的类型参数」和「这是一个具名结构体」，
`Query.ResolveTypeRef` 对 `typeparam` 直接返回 `nil`。

## 防止重复解析

- 文件级：`p.parsedFiles` 记录已解析文件的绝对路径，重复跳过
- 包级：`p.project.Packages[pkgPath]` 已存在则复用，不重建
- 目录级：`ParseProject` 的 `filepath.Walk` 每个目录只走一次

当前模型**不做**「递归解析未解析类型」——跨包只记录 `TypeRef`（名字 + 包路径），
具体类型定义由 `Query.ResolveTypeRef` 在需要时按名字反查 `project.Packages`。
因此不存在「解析到一半的类型打标记、最后统一补解析」的阶段。

## 泛型的解析

- **结构体泛型**（Go 1.18）：`Type.Generic` 记录声明，字段里的类型参数引用保持
  `kind: "struct"`（字段侧标记是后续项）。
- **自由函数泛型**（Go 1.18）：`Func.Generic` 记录声明，参数/返回值里的引用会被标记为
  `kind: "typeparam"`。
- **方法泛型**（Go 1.27）：`Func.Generic` 记录方法自身声明的类型参数；
  接收器上的结构体类型实参在 `Func.Recv.Generic.args`。两者分离存储，不混淆。
- **不做实例化推断**：泛型的具体类型只在调用点可知，astp 作为静态解析器只保留「已声明」
  的占位，不推断 `final` 底层类型，也不展开调用点实参。
